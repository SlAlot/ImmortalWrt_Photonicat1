# 依赖与上游兼容性检查（2026-10-22）

本次检查依据为 v1.0 对应的成功构建日志、最终配置、实际安装清单，以及 `sources.lock.json` 固定版本的源码。报告区分源码可确认的问题与需要实机复现的问题。

v1.0 安装清单共 500 个包，其中 8 个包有直接冲突声明；按实际安装名称交叉核对，未发现直接互斥包同时安装。版本约束和完整依赖闭包仍由构建时的包管理器校验，运行时的端口、路由与设备占用需要另外检查。

## 已修复

| 项目 | 证据与处理 |
| --- | --- |
| QModem USB 扫描开关丢失 | Next 的 USB 开关默认值为 `1`，保存时可能移除默认值；后端在选项缺失时默认 `0`，出厂配置也没有该项。显式保存 USB/PCIe 开关，并在首次初始化启用 USB 扫描。上游反馈见 [QModem #279](https://github.com/FUjr/QModem/issues/279)。 |
| 开机扫描生命周期 | 固定源码把延迟扫描放在后台子 shell。改用 procd 管理的单次扫描进程，等待守护进程就绪，并限制重试和单次请求时间；用户关闭扫描或阻止自动探测时不执行扫描。原有 `start_delay` 正值由该进程处理。 |
| FM350 运营商显示 Generic | `fibocom_get_carrier()` 把非空占位符 `Generic` 当成有效值，跳过 `AT+COPS?`。针对该占位符回退到标准运营商查询，保留真实的专用配置名称。见 [#279 的分析与复现](https://github.com/FUjr/QModem/issues/279#issuecomment-5842467553)。 |
| 多 WAN 与卸载默认值 | 软件和硬件流量卸载默认均开启。是否实际进入硬件转发需核对驱动、流状态和数据路径，不能将硬件选项勾选等同于硬件 NAT 已生效。保留加速能力，并对断线恢复和代理组合做专项实测；依据为 [Linux flowtable 的旁路与缓存语义](https://docs.kernel.org/networking/nf_flowtable.html)。 |
| 竞争的出口管理器 | 保留原有 MWAN3；在最终配置与安装清单中禁止另一套 `qmodem-uplink-manager` 及其界面，防止后续误选。其[源码](https://github.com/FUjr/QModem/blob/e00a30645228aec929d3265c383ef29866eada9c/application/qmodem_uplink_manager/root/usr/share/qmodem-uplink/settings.sh)也主动拒绝与运行中的 MWAN3 同用。 |
| MT7921/MT7922 覆盖 | v1.0 已包含 `mt7921e` 和两种芯片的固件；此次补入 `mt7921u`、`mt7921s`、`mt792x-usb`，并将驱动、固件列入配置与镜像安装清单检查。MT7922 PCIe 共用 mt7921e，无单独的 mt7922e 包。以[固定 mt76 包定义](https://github.com/immortalwrt/immortalwrt/blob/96f566f4a4d04ab44592314bc0279ba9e7de3de0/package/kernel/mt76/Makefile)为准。 |

所有 feed 修改使用精确上下文保护；源码变化不匹配时停止构建，要求重新审查。未替换整个上游脚本，也未改动调制解调器协议选择和网络接口所有权逻辑。

## 已确认包含修复或不适用

- **QMI 拨号卡在 SIM 就绪、不创建接口**：[QModem #287](https://github.com/FUjr/QModem/issues/287) 已由当前固定提交 `e00a306` 修复，反馈者确认 RM520/8202G 恢复。无需重复套用临时 `tail -1` 绕过补丁。
- **光影猫一代 WAN 无链路**：[ImmortalWrt #2194](https://github.com/immortalwrt/immortalwrt/issues/2194) 最终确认与设备残留的旧 U-Boot 有关。继续检查完整镜像中的 RK3568 loader、U-Boot FIT 和设备标识；不根据早期猜测回退 PHY 代码。完整镜像写入与实机启动仍需用户验证。
- **旧电源管理器**：[ImmortalWrt #1990](https://github.com/immortalwrt/immortalwrt/issues/1990) 涉及旧 `pcat-manager`；当前配置和清单使用替代的 `pcat-mgr`。
- **二代 USB / eMMC 报告**：光影猫二代设备树、USB 和存储报告不直接适用于本项目的一代目标，未据此修改一代设备树。
- **QuickStart/iStore 在菜单中消失**：此前已修复 tar 的 XZ 父选项依赖，并验证最终安装清单。保留禁用前端重新压缩、Lua 兼容层与后端依赖。iStore 当前固定版本已支持 APK。

检查时 ImmortalWrt 的 `openwrt-25.12` 分支与当前固定提交一致，QModem 的 main 也仍为当前固定提交；没有发现应直接升级的后续提交。

## 构建警告的判断

成功构建中仍有未选包的元数据警告，例如 Prosody 的 Lua 5.4 库、QWRT 专用 Quectel CM 和 NSS 驱动。最终配置未启用这些选项，实际安装清单也未包含它们。这些警告不等于当前固件缺少依赖；不为消除警告而引入不适用的驱动。

下载过程存在镜像站 403/404 后回退，以及上游编译器告警；该次完整构建最终成功，源码摘要、必需软件包与镜像检查通过。未将日志中的每个 `error` 字样都视为未解决的编译失败。

## 仍需实机验证

- MWAN3 在 OpenWrt 25.12 仍存在 iptables/nftables 迁移限制，见[上游说明](https://openwrt.org/docs/guide-user/network/wan/multiwan/mwan3)。本项目保留固定版本的 iptables-nft 兼容路径与所需模块；需在默认开启卸载的配置下实测断线、恢复、路由器自身流量和代理组合。
- PassWall 与 OpenClash 可以同时安装；应避免同时接管相同流量、DNS 和端口。QModem 的另一套出口管理器不与当前 MWAN3 同装。
- MT7921/MT7922 的实际设备 ID、连接方式、AP 功能、频段和无线配置仍需根据网卡验证；本次未加入蓝牙，也不承诺任意 USB 网卡适用。
- QuickStart 的主题样式、温度、存储字段，以及 iStore 所下载应用的内核 ABI/架构仍取决于实际环境，见 [COMPATIBILITY.md](COMPATIBILITY.md)。
- 默认根分区 1 GiB，Docker 数据建议迁移到合适的独立 ext4 存储。

新增回归检查覆盖扫描服务延迟就绪、禁用与取消、超时退出、运营商回退、procd 进程注册、竞争路由管理器和 Wi-Fi 固件缺失拦截。自动检查不能替代硬件验收。

23 项 Linux 回归测试已通过。默认软、硬件卸载均开启的替代 [v1.1 构建](https://github.com/SlAlot/ImmortalWrt_Photonicat1/actions/runs/39703148374)已启动；此前关闭卸载的构建已取消。该结果不等于固件已编译完成或已经实机验证。卸载能力及 GitHub 项目研究见[专项报告](OFFLOADING-RK3568.md)。
